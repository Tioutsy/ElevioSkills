# ELEVIO Skills — Gamification & Competition Operations Manual

## 1. Overview & Architecture

The ELEVIO Skills gamification engine (Sprints 14.0–14.7) is an enterprise-grade engagement, recognition, and analytics platform designed to motivate employees to complete sustainability learning pathways, pass assessments, and log verifiable workplace impact actions.

### Core Architecture Principles:
1. **Immutable Score Ledger**: Every point awarded or corrected is logged in `elevio_score_ledger` with unique event types, audit timestamps, and idempotency keys. History is never deleted.
2. **Materialized Scores**: The `employees.elevio_score` column caches lifetime points for low-latency queries and is deterministically reconciled against the immutable ledger sum.
3. **Monthly Seasons**: Monthly competitions compute rankings using events within strictly defined date boundaries (`start_date` to `end_date`), resetting monthly while keeping lifetime scores intact.
4. **Zero-Point Recognition**: Unlocking achievements (milestones/badges) awards 0 additional ELEVIO Score points, ensuring achievements serve as pure recognition without inflating competitive standings.
5. **Non-Punitive Anomaly Diagnostics**: Automated scans flag potential fairness or data-integrity discrepancies for administrative review without automatically penalizing or suspending learners.
6. **Strict Tenant Isolation**: All endpoints, calculations, leaderboards, and CSV exports enforce company isolation so no organisation can view or access another tenant's learners or records.

## 2. Point Economics & Scoring Mechanics

Points are awarded deterministically for legitimate learning milestones:

| Event Type | Event Code | Base Points | Description |
| :--- | :--- | :--- | :--- |
| **Course Completion** | `COURSE_COMPLETED` | +100 | Awarded upon completing all mandatory lessons and modules in an accredited course. |
| **Knowledge Assessment** | `QUIZ_PASSED` | +50 | Awarded upon achieving the required passing score on a module quiz. |
| **Score Performance Bonus** | `QUIZ_SCORE_BONUS` | +15 / +25 / +40 | Tiered bonus: 80–89% (+15 pts), 90–99% (+25 pts), 100% (+40 pts). |
| **First-Attempt Excellence** | `FIRST_ATTEMPT_PASS` | +20 | Awarded when passing the quiz assessment on the learner's first genuine attempt. |
| **Interactive Simulation** | `INTERACTIVE_ACTIVITY_COMPLETED` | +25 | Awarded upon successfully completing an interactive branching scenario or simulation. |
| **Workplace Action** | `WORKPLACE_ACTION_COMPLETED` | +50 | Awarded when logging a practical workplace sustainability initiative. |
| **Company Challenge** | `CHALLENGE_COMPLETED` | +25 to +150 | Bonus points awarded upon fulfilling an active company challenge criteria. |

## 3. Department Competitions (`TEAM_SCORE_V1`)

To ensure fair competition across departments of varying sizes, team scores are calculated using the `TEAM_SCORE_V1` normalized formula:

$$\text{Team Score} = (\text{Performance Score} \times 0.70) + (\text{Participation Score} \times 0.30)$$

Where:
- **Performance Score**: The average seasonal score among all active members in the department.
- **Participation Score**: $\left(\frac{\text{Active Participants}}{\text{Eligible Members}}\right) \times 100$.
- **Minimum Eligibility**: Departments must have at least 3 eligible members to receive an official ranking.
- **Historical Transfer Attribution**: When a learner transfers from Department A to Department B, points earned prior to the transfer date remain credited to Department A's season history. Points earned post-transfer attribute to Department B.

## 4. Learner Privacy Controls

ELEVIO Skills respects learner preferences regarding public leaderboard visibility:
1. **Full Name** (`full_name`): Standard identification showing the learner's first name and surname.
2. **Initial Mode** (`initial`): Masks surname to the first initial (e.g., `John D.`).
3. **Anonymous Mode** (`anonymous`): Replaces name with a neutral identifier (e.g., `Learner #1024`) and masks email address in both leaderboard APIs and company CSV exports.

Learner formal course completions, certifications, and compliance records remain fully intact regardless of the privacy display preference selected.

## 5. Platform Admin Operations & Anomaly Management

### Automated Anomaly Diagnostics vs. Manual Metric Reviews

The diagnostic engine strictly differentiates between **automated anomaly flags** (which generate actionable items in the review queue) and **dashboard metric indicators** (which are visual aggregations intended for human context):

#### 1. Automated Anomaly Diagnostics (Generated by `runGamificationDiagnostics()`):
- `SCORE_MISMATCH` (Severity: HIGH): Flagged when an employee's materialized `elevio_score` differs from the sum of non-reversed rows in `elevio_score_ledger`.
- `SUSPICIOUS_VELOCITY` (Severity: REVIEW): Flagged when a learner registers $\ge 5$ course completions within a 10-minute window or $\ge 500$ points within 1 hour.
- `SEASON_INTEGRITY` (Severity: REVIEW): Flagged when multiple overlapping active seasons exist for a single organisation or when an active season has passed its scheduled end date without finalization.
- `CHALLENGE_FAIRNESS` (Severity: INFO): Flagged when a company challenge has $< 10\%$ employee participation after being active for $\ge 7$ days.
- `DIFFICULT_INTERACTION` (Severity: REVIEW): Flagged when an interactive learning module shows a high abandonment rate ($\ge 2$ retries with $< 50\%$ first-attempt pass rate).

#### 2. Administrative Metric Indicators (Surfaced in Dashboards for Human Inspection):
- **Competition Concentration %**: Displayed in the Company Engagement Dashboard (`/company/engagement-competition`) calculating the percentage of seasonal points held by the Top 10 learners.
- **Interactive Retry Averages**: Surfaced in Engagement Analytics to help learning designers identify modules that may require clearer instructional guidance.
- **Off-Hours Activity Distribution**: Viewable in Platform Health charts to distinguish between daytime corporate learning and evening self-directed study.

#### 3. Future Roadmap Considerations:
- Automated IP-velocity tracking across multi-factor authenticated sessions.
- Multi-company aggregate benchmarking by industry sector.

### Controlled Score Reconciliation
When a discrepancy exists between an employee's materialized score and their immutable ledger sum:
1. The Platform Admin navigates to `/platform-admin/gamification-health` and opens the **Score Recalculation Modal**.
2. The modal displays:
   - Employee Name & Email
   - Organisation Name
   - Current Materialized Score vs. Immutable Ledger Sum
   - Calculated Difference ($\Delta$)
   - Mandatory Justification Input
3. Upon confirmation, `recalculateEmployeeScore()` executes a transaction-safe synchronization:
   - Recomputes $\sum \text{Points}$ for non-reversed ledger transactions.
   - Updates `employees.elevio_score`.
   - Auto-resolves open `SCORE_MISMATCH` anomaly records for the employee.
   - Records an immutable audit log entry in `audit_logs`.
   - Leaves ledger transaction history, course completions, and certificates completely untouched.

## 6. Reversal & Correction Label Taxonomy

When score events are displayed to learners or administrators in `formatScoreEventDisplay()`, non-punitive, objective terminology is strictly enforced:

| Underlying Reason / Condition | Learner Display Title | Learner Display Description |
| :--- | :--- | :--- |
| **Duplicate Award** | `Score Entry Corrected` | `Duplicate award reversed` |
| **Challenge Correction** | `Score Entry Corrected` | `Challenge award corrected` |
| **Ledger Cache Reconciliation** | `Score Cache Reconciled` | `Score cache reconciled` |
| **Administrative Correction** | `Administrative Score Correction` | `Administrative score correction` |
| **General Known Correction** | `Score Entry Corrected` | `Score entry corrected` |
| **Unknown / Historical Fallback** | `Score Adjustment` | `Score adjustment` |

Operator internal notes and investigative comments are strictly restricted to the administrative audit log and are never exposed to learners.

## 7. CSV Export Security & Data Handling

Both Company Admin and Platform Admin exports enforce strict data protection:
- **Anti-Formula Injection**: All text fields starting with spreadsheet formula symbols (`=`, `+`, `-`, `@`, `\t`, `\r`, or leading whitespace followed by these symbols) are automatically escaped with a leading apostrophe (`'`) to prevent execution in Microsoft Excel, Apple Numbers, and Google Sheets.
- **Metadata Provenance**: Exports include metadata headers documenting the ISO generation timestamp, organisation scope, and season date window.
- **Privacy Masking**: Anonymous learners have their names and emails masked in Company Admin exports (`Learner #ID` and `[Hidden - Opted Out]`).

## 8. Incident Response & Safe Rollback Runbook

### If Score Recalculation Discrepancies Occur:
1. Trigger an on-demand diagnostic scan via `POST /api/platform-admin/gamification/anomalies/diagnose`.
2. Inspect the anomaly queue at `/platform-admin/gamification-health`.
3. Verify that the score ledger (`elevio_score_ledger`) contains the canonical completion records.
4. Execute `recalculateEmployeeScore` with an audited reason.

### If Competition Features Must Be Disabled for an Organisation:
Company Admins or Platform Admins can disable individual and department competitions via `PUT /api/company/competitions/settings`:
```json
{
  "enabled": false,
  "departmentCompetitionEnabled": false
}
```
Disabling competition hides the leaderboards immediately without deleting score history or resetting earned achievements.

### Safe Rollback Procedures:
1. **Frontend Reversion**: Deploy previous web client bundle. The backend API is backward-compatible with legacy clients.
2. **Feature Toggle Pause**: Set `companiesTable.leaderboardEnabled = false` for any company requiring immediate competition freeze.
3. **Database Integrity**: Never drop or modify `elevio_score_ledger`, `certificates`, `courses`, or `enrollments`. Historical ledger data is append-only and safe against rollbacks.
